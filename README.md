# Борд группы 15.27Д-С01/25б

Одна страница на группу: расписание всего семестра, калькулятор баллов по
балльно-рейтинговой системе РЭУ, контрольные точки и общая доска дедлайнов.
Открывается с телефона, ничего устанавливать не надо.

Личных данных на странице нет. Калькулятор считает прямо в браузере, введённые
пропуски и баллы никуда не уходят и никому не видны.

## Что здесь лежит

| Файл | Зачем |
|---|---|
| `index.html` | вся страница: вёрстка, логика, калькулятор |
| `data.js` | расписание и учебный план, генерируется скриптом — руками не править |
| `config.js` | адрес и ключ Supabase для доски дедлайнов |
| `build_schedule.py` | тянет расписание с rasp.rea.ru и пересобирает `data.js` |
| `supabase.sql` | создаёт таблицу доски и права доступа |
| `.github/workflows/update-schedule.yml` | раз в неделю обновляет расписание сам |
| `party.html` | световое шоу: то, что открывают в Телеграме одногруппники |
| `party-control.html` | пульт ведущего: цвета, эффекты, звук на весь зал |
| `party-core.js` | движок шоу: связь и синтез звуков |

## Запуск: три шага

### 1. Репозиторий и сайт

Репозиторий — https://github.com/LockerBig007/rea-board, `origin` уже прописан.
Отправить из этой папки:

```bash
git push -u origin main
```

Дальше в репозитории: **Settings → Pages → Source: Deploy from a branch →
Branch: `main`, папка `/ (root)` → Save.** Через минуту-две сайт будет по адресу
**https://lockerbig007.github.io/rea-board/** — эту ссылку и кидайте одногруппникам.
В адресе Pages логин всегда строчными буквами, это нормально.

### 2. Доска дедлайнов

Без этого шага страница работает как справочник, только блок «Доска группы»
будет пустым.

1. Зарегистрироваться на [supabase.com](https://supabase.com), создать проект
   (бесплатный тариф, регион ближе к Европе).
2. **SQL Editor → New query**, вставить содержимое `supabase.sql`, нажать Run.
3. **Project Settings → API**: скопировать `Project URL` и ключ `anon public`.
4. Вписать оба значения в `config.js`, закоммитить и запушить.

Ключ `anon` публичный по замыслу — он и должен лежать в коде страницы. Секретный
`service_role` сюда класть нельзя.

Логинов у одногруппников нет, поэтому добавлять записи и отмечать сделанным
может любой, кто открыл ссылку. Кнопка удаления показывается только автору
записи. Если доску засорят — Table Editor в Supabase, удалить лишнее.

### 3. Автообновление расписания

Ничего делать не нужно: воркфлоу включается сам после пуша и по воскресеньям в
10:00 МСК перезабирает расписание. Проверить или запустить вручную —
вкладка **Actions → Обновить расписание → Run workflow**.

Если расписание понадобится обновить с компьютера:

```bash
python build_schedule.py
git add data.js && git commit -m "Расписание" && git push
```

## Новый семестр

В `build_schedule.py` поменять `PLAN` (учебный план из личного кабинета:
Рабочий учебный план → нужный семестр), `SEMESTER` (даты из графика учебного
процесса) и при необходимости `WEEKS`. Затем запустить скрипт.

Балл за одно посещение считается как 20 ÷ число пар, а число пар — это
контактные часы из учебного плана, делённые на два. Эта формула проверена на
фактических баллах из раздела «Рейтинг» личного кабинета и совпадает с
расписанием по каждому предмету.

## Световое шоу в Телеграме

Зал держит телефоны, экраны красятся в цвет по команде со сцены, по сигналу со
всех устройств одновременно бьёт звук. Одногруппники никуда не переходят:
приложение открывается внутри Телеграма, а сайт нужен только ведущему.

### Что где открывать

| Кто | Что |
|---|---|
| зал | `party.html` — внутри Телеграма, по ссылке на мини-приложение |
| ведущий | `party-control.html` — на ноутбуке, с которого идёт показ |

Обе страницы должны быть в одной «комнате». По умолчанию это `rea`; чтобы
развести несколько шоу, добавьте `?room=код` в оба адреса.

### Подключить мини-приложение: один раз, пять минут

1. В Телеграме открыть **@BotFather** → `/newbot`, задать имя и адрес бота.
2. `/newapp` → выбрать этого бота → название, короткое описание, картинку
   640×360, затем **Web App URL**:
   `https://lockerbig007.github.io/rea-board/party.html`
3. BotFather выдаст ссылку вида `t.me/ваш_бот/имя_приложения`. Её и кидать в
   чат группы и закреплять — тап по ней открывает шоу внутри Телеграма.

Сервер и вебхук не нужны: мини-приложение — обычная страница с GitHub Pages,
а события летают через тот же Supabase, что и доска дедлайнов. Таблицы тоже не
нужны, в базу ничего не пишется.

### Как вести

Пульт слушается с клавиатуры, чтобы не целиться мышью на виду у зала:

| Клавиша | Что делает |
|---|---|
| `1`…`9` | звуки: БАБАХ, фанфары, та-дам, аплодисменты, дробь, сирена, лазер, тревога, щелчок |
| пробел | вспышка на всех экранах |
| `W` | волна: цвет бежит по залу от первого подключившегося к последнему |
| `R` | радуга: каждому телефону свой оттенок |
| `E` | искры: случайные вспышки вразнобой |
| `S` | стробоскоп |
| `0` | погасить всё |

Порядок в волне — это порядок подключения, а не рассадка. Хотите волну слева
направо — пусть включаются по очереди с левого края.

### О чём предупредить зал

- **Айфоны**: беззвучный режим глушит звук. Переключатель сбоку должен быть
  выключен, иначе хор пройдёт мимо.
- **Экран не гасить** и не сворачивать Телеграм — погасший телефон выпадает.
- **Стробоскоп** — частое мигание, опасное при светочувствительной эпилепсии.
  Частота ограничена в коде, но если кто-то предупреждал о такой особенности,
  лучше не включать его совсем.

Кнопку «БАБАХ» у зала (вспышка и щелчок у всех сразу) можно запретить галочкой
на пульте — например, на время серьёзной части выступления.

## Лекции

Оцифрованные конспекты лежат в папке `lectures/` обычными текстовыми файлами,
а страница `lectures.html` раскладывает их по предметам из учебного плана.
Предметы берутся из `data.js`, поэтому полки появляются сами и видно, по каким
дисциплинам конспектов ещё нет.

| Файл | Зачем |
|---|---|
| `lectures.html` | список предметов, по клику раскрывается список лекций |
| `lecture.html` | показ одного конспекта |
| `lectures.js` | **список лекций — единственное, что правится руками** |
| `lectures/` | сами конспекты и картинки к ним |
| `lectures/shablon.md` | образец оформления |
| `lectures/*.pdf` | готовые конспекты одним файлом, для скачивания |
| `build_lecture.py` | собирает свёрстанный конспект в пару HTML + PDF |
| `site.css` | общие стили новых страниц |

### Добавить лекцию

1. Положить файл в `lectures/` с латинским именем. Три варианта:

   - **`.html` вместе с `.pdf`** — основной вариант. Страницу читают на сайте,
     PDF скачивают. Такую пару делает `build_lecture.py`, см. ниже.
   - **`.pdf` сам по себе** — если страницы нет. Откроется как PDF.
   - **`.md`** — текст конспекта, его показывает читалка `lecture.html`.
     Картинки кладутся туда же.

2. Дописать строку в `lectures.js` (формат объяснён в самом файле):

   ```js
   { subject: "Статмоделирование", title: "Введение", date: "15.09.2026",
     file: "lectures/statmodel-01.html", pdf: "lectures/statmodel-01.pdf" },
   ```

   Название предмета должно совпадать с тем, что на главной — коротким или
   полным. Не совпадёт — лекция уедет в полку «Разное».
3. Закоммитить и запушить.

### Как писать конспект

Как написано в файле, так и покажется: перевод строки даёт новую строку,
пустая строка — новый абзац. Разметка нужна только там, где хочется
заголовка, списка или формулы — всё показано в `lectures/shablon.md`.

Формулы пишутся между знаками доллара: `$\sigma^2$` в строке, `$$...$$`
отдельной строкой. Отрисовывает KaTeX, подключённый с CDN.

### Готовый свёрстанный конспект

Если конспект уже свёрстан отдельной страницей, его не надо переписывать в
Markdown. Скрипт соберёт из него то, что нужно сайту:

```bash
python build_lecture.py "путь/к/конспекту.html" lectures/имя.html
```

Получится два файла рядом: `имя.html` для чтения на сайте и `имя.pdf` для
скачивания. В реестр тогда пишутся оба:

```js
{ subject: "Статмоделирование", title: "Конспект курса", date: "01.10.2026",
  file: "lectures/statmodel.html", pdf: "lectures/statmodel.pdf" },
```

Что делает скрипт:

- вшивает картинки прямо в HTML, пережимая их, — страница открывается с диска
  и без интернета, отдельная папка с картинками не нужна;
- принудительно включает светлую тему: конспект читают как лист бумаги;
- раскладывает текст по листам A4 с номерами страниц — на экране, в PDF и на
  печати разбивка одна и та же;
- на телефоне (уже ниже 900 точек) листы выключаются, остаётся обычная лента:
  A4 на экране телефона читать невозможно.

Исходник конспекта должен быть целой страницей, с `<!doctype html>` и `<head>`.
Если это только тело страницы, браузер не поймёт кодировку и покажет
кракозябры вместо русского текста.

PDF собирается установленным в системе Chrome. Нет Chrome — HTML всё равно
соберётся, а PDF можно сделать из браузера: Печать → Сохранить в PDF, разбивка
будет та же.

Файл `.nojekyll` в корне нужен, чтобы GitHub Pages отдавал `.md` как есть и не
пытался собрать из них сайт. Удалять его нельзя.
